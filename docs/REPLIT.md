# Replit as a development, verification and reconstruction candidate
Replit is a hosted commercial development platform, not an open-source replacement for REA. Consider in every case (record relevance or not applicable), with an in-depth target-specific review when it could help. Recheck current [official docs](https://docs.replit.com/), [documentation index](https://docs.replit.com/llms.txt), [changelog](https://replit.com/changelog) and [pricing](https://replit.com/pricing) before selecting. Do not assume plan entitlements or costs.
## Initial documentation review — 2026-11-25
- [Version control](https://docs.replit.com/replit-workspace/workspace-features/version-control): GitHub import, push, branches, checkpoints/rollback, Git CLI. Candidate: import approved production repository/handoff, review branch diffs, return tested commits to GitHub as authoritative state. Test export/rebuild outside Replit.
- [Task board](https://docs.replit.com/references/agent/task-board): planned work, isolated task copies, dependent tasks, review and apply changes. Candidate: map reconstruction backlog, acceptance tests and scoped tasks; review work log before merge.
- [Agent skills](https://docs.replit.com/replitai/skills): project-level .agents/skills and selective context, cross-agent rulesync. Candidate: port reviewed build/evidence rules, not proprietary research or secret data; verify compatibility.
- [App testing](https://docs.replit.com/references/agent/app-testing): browser-based application testing as documented; independently verify critical flows with explicit test receipts. Compare to Playwright fixtures and run outside platform where feasible.
- [Code optimizations](https://docs.replit.com/references/agent/code-optimizations): optional review/simplification stage; compare actual regression/cost with baseline, do not assume benefit.
- Also assess runtime/language/package restrictions, database, secrets, authentication, integrations, scheduled jobs, deployments and observability from current official docs as target warrants. Do not equate hosted capabilities with portable dependencies.
## Selection checklist
Compare Replit with Cursor/local Claude/Codex and other authorized build environments: support for target runtime and native artifacts, Git round-trip, reproducible dependency lock/build, environment variables/credential names only, DB migration/export/restore, tenant isolation, external APIs, browser test coverage, logging, deployment availability/cost and portability. Replit is particularly a candidate for independently implemented web/API/agent prototypes and test deployments, not assumed compatible with REA/Ghidra/CDP/native or desktop/mobile pipelines. Verify local fixture before choosing any integration. Record which parts require a hosted service and alternatives, test output, budget and ownership. No upload of private target data, credentials or unapproved proprietary assets; request permission before connecting accounts, spending or publishing. Use approved synthetic fixtures. Record evidence and comparative outcomes in target case; promote reusable findings through learning review only.
Initial review was official documentation, not an actual Replit account run, deployment, pricing audit or tool integration test.
