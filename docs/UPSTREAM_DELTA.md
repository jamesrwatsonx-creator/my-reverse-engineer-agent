## Implementation constraints inherited by later phases
- Prefer native REA when its live operation and fixture cover the obligation. Treat documentation as a source observation, not an invocation receipt. Compare installed release with this commit before using new options.
- Distinguish acquisition, provider computation, retained evidence, transport and client receive limits. Record effective settings and failure reason, recover retained data first; never blindly rerun. A source change after capture does not make a historical evidence view current.
- Evidence coverage is bounded, and external evidence cannot masquerade as canonical REA Evidence. Keep independent gate results and unresolved claims; no private server or protected content recovery claims.
- Existing planning docs already anticipate most of these changes (ADVANCED_ANALYSIS, UPSTREAM_REVIEW, FIDELITY_AND_HANDOFF); this is a reconciliation, not a claim of previously missing capabilities. Full source implementation and installed integration tests remain outstanding.
