## Composition patterns (proposals, not verified adapters)
- State/business rules: authorized observations -> AALpy/LearnLib model or own Daikon traces -> Z3/explicit decision table -> Hypothesis/fast-check held-out tests. Invariants from own replacement do not establish original target internals.
- Background workflows: sanitized ordered event table -> PM4Py process model/conformance -> explicit TLA+ specification -> TLC counterexample -> Temporal/independent workflow and integration tests.
- Data/API: permitted sample schema -> Quicktype/OpenAPI or Kaitai parser as appropriate -> Testcontainers/WireMock -> Schemathesis/fast-check/Hypothesis. Pin each parser/runtime, retain schema hashes and fixture outputs.
- Performance: approved independent deployment -> k6 OR Locust, same workload -> OpenTelemetry if instrumented -> comparable measurements and SLO result. Never use live third-party load to infer backend capacity.
- Migration: approved own source -> OpenRewrite recipe/dry-run -> test baseline vs candidate -> commit reviewed diff; do not rewrite original proprietary code.
Use one tool when adequate. Correlate run/scenario/step and evidence IDs; record exact artifact schemas, actual installed versions, permissions, fixture receipts and fallback; independently prove each composition before promotion.
