# ChatGPT target preparation
Identify target URL/repo/artifact and type from accessible docs. Ask only unknown consequential questions, preferably 0–3 in one round:
- Goal: research, selected capabilities, closest observable fidelity, or improve? Which features must match/exclude; intended use and destination?
- Access: public/demo/approved account, OS/version/browser, official artifact or authorized local path, API docs/sandbox or commit, as relevant. Never ask for passwords in chat; use local login/scoped credential storage.
- Constraints: critical acceptance, budget, licensing, runtime, deployment and approved build scope if relevant.
If missing access, proceed with permitted public documentation and mark blocker. Record literal owner request, choices and assumptions separately. Default research-only without build approval. Reuse canonical slug, preserve historical evidence. Create BRIEF.json, README, features, experience, architecture, evidence, capabilities, opportunities, STATUS, GAP_MATRIX, SCENARIOS, TOOL_PLAN, HANDOFF, LAUNCH and feature dossiers when identified. Seed only documented facts and dated URLs, no fabricated observations. Preserve and update registry/index.json, commit scoped changes. Return target link and owner-specific paste-ready launch prompt. Coding agent resumes, not repeats research unless evidence stale.

## Permanent intake history
Initialization can occur before a target is supplied: read AGENTS, README, workflow, toolchain, knowledge index and transfer instructions, report ready without creating a dummy investigation. Once target is known, inspect its permitted public sources and read relevant prior cases. Ask only missing essentials; clarify scope vs fidelity, target platform/artifact, intended destination and critical outcomes. Save dated exact non-sensitive questions and responses (including unasked/unknown and changed decisions) in INTERVIEW.md, original goal and scope in BRIEF.json, accepted choices and rationale in DECISIONS.md. Do not invent answers or silently collapse original requests into assumptions. CONTEXT.json captures instruction commit, tool registry revision, knowledge revision/IDs actually retrieved, planned tools, scope and stale/revalidation concerns. Snapshot relevant IDs and hashes, not redundant copies of all universal documents. Update before LAUNCH and record any context refresh during execution.

First-stage upstream review: before target planning (including when initialized without a target), inspect original REA and Replit per docs/UPSTREAM_REVIEW.md and REPLIT.md. When target is known, save dated review in its UPSTREAM_REVIEW.md; CONTEXT.json links to it. Recheck at coding-agent launch, retain dated entries, do not invent a review.

Mandatory all-resource refresh: follow docs/RESOURCE_FRESHNESS.md at every investigation (full catalog and tracked owner sources, current upstreams, owner-profile discovery, change assessment and per-target relevance), record receipt in UPSTREAM_REVIEW.md and reference immutable report. Recheck selected versions before execution. Never silently auto-update or mark unreviewed changes as adopted.

After reconnaissance and owner scope, follow docs/GAP_ENGINE.md and GAP_TOOL_RECIPES.md. Populate GAP_REGISTER.json with scoped obligations and explicit gap classes; run gap_engine.py plan --slug <target>, choose verified tools by evidence and gap, record attempts/fixtures/results/residuals, run audit at handoff and route reusable lessons through LEARNING_DELTA. Do not use irrelevant or unauthorized tools. No arbitrary fidelity percentage.
