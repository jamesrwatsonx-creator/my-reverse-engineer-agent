# Learning records and local CLI
LEARNING_DELTA.json: schema_version, target_slug, assessment PENDING/ASSESSED/NO_CHANGE, no_change_reason, items[]. Each item: id (kebab-case unique within case), capability_id (canonical kebab-case), kind (see LEARNING), proposer (run identity), summary, context (constraints), limitations, aliases[], evidence [{path: repo-relative artifact, sha256: bytes digest}], fixture_receipt {path,sha256}, fixture_result PASS/FAIL, license_review PASS/other, privacy_review PASS/other, optional comparison {path,sha256} and claims_improvement boolean. Record prior variant IDs, alternative architecture, failure/reversal conditions and raw metrics in case evidence. Include comparison for every VARIANT; if not yet comparable retain needs-retest. For CORROBORATION link canonical capability and prior source; no automatic count or dedupe of independent evidence. For RETRACTION explicitly identify affected IDs and review their deprecation separately. Never erase originals.
CONTEXT.json revisions are exact 40-character Git commits used for instructions, tool registry and knowledge; may be same commit. Store actual retrieved IDs, no pretend retrieval. Audit checks record structure and file hashes, not semantic correctness.
Use search --query, audit --slug, compare --file, review --slug --id --reviewer --decision --reason --receipt <repo-relative separate review artifact>, make-package --slug --source-repo --source-commit --destination --version --readiness --approval, verify-package --slug. Review verifies shape/refs and comparison eligibility, not reviewer identity, independence, authenticity or actual experiments. The human/separate agent must actually review. Search is lexical ranking of all reviewed dispositions (including rejected and needs-retest); status and conditions must be read before use. Validated negative records must not be recommended as successful methods. Global defaults are not changed by review. Concurrent writes: work on branches and reconcile index and history, do not run parallel writes to same local index. Commit after verifying. 
Package generator only hashes the nine explicit reviewed files; it neither populates content nor transfers it. Never put credentials or private material in them. Verify-package detects changes, not completeness.
